# TypeBridge

**手机扫码，文字直接落在电脑光标处。**

电脑上跑一个小程序，手机扫个码打开一个极简网页，在手机上打字（或者用手机输入法自带的语音输入），点发送，文字立刻出现在电脑上当前光标所在的位置。手机上不用装任何 App。

---

## 它解决什么问题

有些场景下，你会很想用手机打字，但字要落在电脑上：

- 电脑前没有顺手的位置放键盘，或者键盘坏了
- 要往电脑上录一大段中文，用手机输入法的语音输入快得多
- 电脑在投屏、在讲课、在演示，人站在离电脑几米外
- 临时用别人的电脑，不想在上面装输入法、不想登录任何账号

常见的绕法都别扭。微信传文件再复制，要切三次窗口。投屏软件为了一个打字功能装了一整套东西。TypeBridge 只想干最上面那一件事。

## 它做什么，不做什么

**做**：一根管子。手机上打出来的字，送到电脑光标处。就这一件事。

**不做**：

- 不做语音识别。语音交给手机输入法，它的识别质量比任何自研方案都好，而且离线、免费。
- 不做文字优化、不纠错、不改写。你打什么就送什么。
- 不调云端模型。文字只在你自己的手机和电脑之间走。
- 不在电脑端做界面。它是一个托盘图标，仅此而已。

## 特点

| | |
|---|---|
| 手机零安装 | 扫码开网页就能用。不装 App，不注册，不登录 |
| 局域网直连 | 手机和电脑直接对话，不经过任何服务器，断网也能用（同一路由器下） |
| 电脑端极小 | 一个 90KB 的单文件 exe。不装运行时，不带任何第三方库 |
| 不挑软件 | 从系统输入层注入，WPS、记事本、浏览器、任何输入框的表现都一样 |
| 打字和语音都行 | 手机输入法支持什么，它就能送什么 |
| 免安装免配置 | 编译完双击就用，不需要管理员权限，不需要改系统设置 |

## 快速开始

### 下载即用（推荐）

到 [Releases](https://gitee.com/lanyacp/TypeBridge/releases) 下载 `TypeBridge.exe`，双击运行。不用编译，不用装任何东西。

1. 程序自动弹出一个配对页，上面有二维码
2. 手机连上同一个 WiFi，用微信扫一扫，或者系统相机扫码
3. 手机页面上出现绿点「已连接」，就可以打字了
4. 打字，点发送，字落到电脑光标处

### 自己编译

需要 .NET Framework 4.x（Windows 10/11 自带）。用系统自带的 `csc.exe`，不需要装 Visual Studio：

```bat
build\build_stage1.bat
```

编译产物在 `build\TypeBridge.exe`（90KB），**双击它就行**，不需要命令行。

程序运行期间右下角托盘常驻一个图标。右键它可以选择：

- **链接二维码**，再打开一次配对页
- **重新生成配对码**，换一个码，旧的连不上
- **暂停注入**，临时不接收文字，比如你去开会了
- **开机自动启动**，勾上以后开机就在后台待着
- **查看日志**，出问题时看这个
- **退出**

关掉配对页不影响使用，程序在托盘里继续跑。想彻底退出就用托盘菜单。

### 其他平台

Linux（银河麒麟 V10）版本的注入层还在开发中，没有包含在本仓库里。手机端页面两个平台是同一套，可以直接复用。

## 工作原理

```
手机浏览器                 局域网                  电脑
┌──────────┐          ┌──────────┐          ┌──────────────┐
│ 输入框    │  WS      │ 手写     │  注入    │ 当前前台窗口  │
│ 打字/语音 │ ───────► │ HTTP +   │ ───────► │ 光标处        │
│ 发送按钮  │ JSON     │ WebSocket│          │              │
└──────────┘          └──────────┘          └──────────────┘
```

电脑端起一个 HTTP 服务，同时在这个端口上手写实现了 WebSocket（RFC6455）。手机扫码打开页面，页面向电脑发起 WebSocket 连接，先发配对码，配对通过后就能发文字了。电脑收到文字，用系统级的输入注入把它打出来。

协议很简单，就是几种 JSON 消息：

| 消息 | 作用 |
|---|---|
| `hello` | 带配对码，握手 |
| `text` | 发一段文字 |
| `sync` | 实时同步模式的增量，退格 N 次再补一段 |
| `enter` / `backspace` | 回车、退格 |
| `ping` | 心跳 |
| `ack` / `error` | 电脑回执。`ack` 带上当前前台窗口标题，手机页面上能看到字要落到哪 |

**实时同步模式**值得一提。手机输入框的默认行为是「打完点发送」，页面上有个下拉可以切成「实时同步」。切过去之后，手机输入框就成了电脑文本的一个镜像，你每敲一个字，电脑上同步出现一个字，删掉也一样。做法是每次算出手机文本相对电脑文本的最长公共前缀，把差异（退格几个字、补哪一段）打包发过去。打字的过程中，拼音组合还没上屏的那一段不会同步，免得把拼音字母传过去。

## 技术要点

几个当时绕不过去的地方，记在这里免得后来人再踩：

**用手写 WebSocket，不用第三方库。** 项目要求零依赖、单文件，手里只有一个 `csc.exe`，于是 `Sec-WebSocket-Accept` 那个 SHA1 加 GUID 是自己算的，帧也是自己拆的。手机页面那头的二维码同样是自己画的（canvas 逐模块填充），因为 CDN 上的库在这个场景里意味着「没有网络就用不了」。

**用 TcpListener，不用 HttpListener。** `HttpListener` 绑定局域网 IP 需要管理员权限或者预先配置 urlacl，那样就破坏了「双击即用」这个前提。`TcpListener` 是普通用户态的 socket，免权限。

**用 SendInput 加 KEYEVENTF_UNICODE 做注入。** 合成 `VK_PACKET` 消息，等效于用户按下了对应字符键，绕开输入法和键盘布局，中文和 emoji 都能打。有个坑是 x64 下 `sizeof(INPUT)` 是 40 字节不是 32，因为 union 被 `MOUSEINPUT` 撑大了，传错大小 `SendInput` 会直接返回 0 失败。

**编译环境有两个硬约束。** 系统自带的 `csc.exe` 只认 C# 5 语法，`nameof`、字符串插值、`?.`、表达式体成员这些都不能用。另外源文件必须是 **UTF-8 with BOM**，没有 BOM 的话 `csc` 会按 ANSI/GBK 读，中文字符串会直接乱掉。

## 安全与隐私

- **文字不经过任何服务器。** 手机和电脑在同一个局域网里直接对话，程序不发任何数据到外网。
- **配对码**。连接建立后第一帧必须带对配对码，否则不接受任何注入指令。配对码是 4 位数字，存在电脑本地，可以在托盘菜单里重新生成。
- **同一时刻只有一个手机连得上。** 新的连接会把旧的顶掉，避免两台设备抢着往一个光标里打字。
- **你能看见字要落到哪。** 每条回执都带着电脑当前前台窗口的标题，手机页面上会显示出来。发之前先看一眼目标对不对。
- **不要用它往聊天软件里灌大段文字。** 这不是安全问题，是实践问题。某些聊天类程序一次接收大量合成输入会卡住。给自己留个心眼，先拿记事本试。

## 已知限制

- **必须同一个局域网。** 不在一个 WiFi 下就用不了。想跨网络用需要自己搭内网穿透（frp、Tailscale 之类），程序本身不管这事。
- **注入目标是「当前前台窗口」**，不是你能指定的某个窗口。发文字之前，电脑上的光标得先停在正确的地方。
- **没有做提权。** 如果目标窗口是以管理员身份运行的（比如某些安装程序），普通权限的注入会无效，这是 Windows 的 UIPI 机制决定的。
- 手机页面没做 PWA、没有离线缓存。断网重连就是刷新页面。

```
src/
  TypeBridge.cs        Windows 版主程序（C# 5，单文件）
  web/                 手机页面，编译时内嵌进 exe

```

## 开发

改完代码后重新编译：

```bat
build\build_stage1.bat
```

有个坑值得先说：如果编译报「另一个程序正在使用此文件」，那是上一次运行的 `TypeBridge.exe` 还占着文件。从托盘菜单退出它，再编译。

源码顶部的注释里记了几个绕不过去的技术点（C# 5 语法限制、源文件必须带 BOM、x64 下 `sizeof(INPUT)` 是 40 字节），动手改之前值得先看一眼。
